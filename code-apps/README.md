# Power Apps Code Apps - Experimentation Project

Power Apps **Code Apps** let developers bring Power Apps capabilities into custom web apps built in a code-first IDE (VS Code). Build with popular frameworks (React, Vue, etc.) while keeping full control over UI and logic, then deploy and run in Power Platform.

This project uses the **official Microsoft Vite template**: `microsoft/PowerAppsCodeApps/templates/vite`

## What Are Code Apps?

Code Apps are a Power Apps feature that bridges pro-code web development with the Power Platform managed environment. Key features:

- **Microsoft Entra authentication and authorisation** built in
- **Access to Power Platform data sources and 1,500+ connectors**, callable directly from JavaScript/TypeScript
- **Easy publishing and hosting** of line-of-business web apps in Power Platform
- **Managed Platform policies** (app sharing limits, Conditional Access, DLP, etc.)
- **Simplified deployment and ALM** via PAC CLI

### Architecture

The architecture has three layers:

| Layer | Purpose |
|-------|---------|
| **Your code** | React/TypeScript app (this project) |
| **Power Apps SDK** | `@microsoft/power-apps` npm package - provides APIs, generates models/services for connectors |
| **Power Apps Host** | Manages end-user auth, app loading, and runtime hosting |

Key files:

| File | Purpose |
|------|---------|
| `power.config.json` | Generated by SDK - contains metadata for Power Platform connections and publishing (do NOT edit manually) |
| `src/generated/` | Auto-generated typed TypeScript models and services when you add data sources via PAC CLI |
| `vite.config.ts` | Vite config with `powerApps()` plugin from `@microsoft/power-apps-vite` |

1. **Enable Code Apps** on your Power Platform environment:
   - Go to [Power Platform Admin Centre](https://admin.powerplatform.microsoft.com/)
   - Navigate to: Manage > Environments > select environment > Settings > Product > Features
   - Toggle **Enable code apps** ON
   - Save

2. **Licence**: End-users running code apps need a **Power Apps Premium** licence

## Quick Start

### 1. Install Dependencies

```powershell
cd code-apps
npm install
```

### 2. Authenticate PAC CLI

```powershell
pac auth create
pac env select --environment <Your-Environment-ID>
```

Sign in with your Power Platform account when prompted.

### 3. Initialise the Code App

```powershell
pac code init --displayname "My Code App"
```

This generates `power.config.json` which links this project to Power Platform.

### 4. Run Locally

```powershell
npm run dev
```

Open the **Local Play** URL in the same browser profile as your Power Platform tenant.

> **Browser Note**: Since December 2025, Chrome/Edge block requests from public origins to localhost by default. You may need to grant Local Network Access permission.

### 5. Deploy to Power Apps

```powershell
npm run deploy
# (equivalent to: npm run build && pac code push)
```

If successful, this returns a Power Apps URL to run the app. You can also see it in [Power Apps](https://make.powerapps.com/).

## Connecting to Data

### Adding Connectors (1,500+ available)

1. **Create connections** at [Power Apps](https://make.powerapps.com/) > Connections
2. **Get connection metadata**:

   ```powershell
   pac connection list
   ```

3. **Add to your app**:

   ```powershell
   # Non-tabular (e.g., Office 365 Users)
   pac code add-data-source -a "shared_office365users" -c "<connectionId>"

   # Tabular (e.g., SQL)
   pac code add-data-source -a "shared_sql" -c "<connectionId>" -t "[dbo].[TableName]" -d "server.database.windows.net,dbname"
   ```

This auto-generates typed TypeScript models and services in `src/generated/`.

### Connecting to Dataverse

```powershell
pac code add-data-source -a dataverse -t <table-logical-name>
```

Example - add accounts table:

```powershell
pac code add-data-source -a dataverse -t account
```

This generates `AccountsModel.ts` and `AccountsService.ts`. Use them like:

```typescript
import { AccountsService } from './generated/services/AccountsService';
import type { Accounts } from './generated/models/AccountsModel';

// CRUD operations
const accounts = await AccountsService.getAll({
  select: ['name', 'accountnumber'],
  filter: "address1_country eq 'USA'",
  top: 50
});

const newAccount = await AccountsService.create({
  name: "New Account",
  accountnumber: "ACC001"
} as Omit<Accounts, 'accountid'>);

await AccountsService.update(accountId, { name: "Updated Name" });
await AccountsService.delete(accountId);
```

**Supported Dataverse operations**: Create, Retrieve, RetrieveMultiple, Update, Delete, Filter, Sort, Top, Paging.

### Discovering Data Sources

```powershell
# List datasets for a connection
pac code list-datasets -a <apiId> -c <connectionId>

# List tables in a dataset
pac code list-tables -a <apiId> -c <connectionId> -d <datasetName>

# List SQL stored procedures
pac code list-sql-stored-procedures -c <connectionId> -d <datasetName>
```

### Deleting Data Sources

```powershell
pac code delete-data-source -a "shared_sql" -ds "MobileDeviceInventory"
```

> **Note**: If a connection schema changes, delete the data source and re-add it — there's no refresh command.

### Using Connection References (for ALM)

For portable solutions across Dev/Test/Prod, use connection references instead of direct connections:

```powershell
pac code add-data-source -a <apiName> -cr <connectionReferenceLogicalName> -s <solutionID>
```

## Getting Context Data

Use `getContext()` to retrieve app and user metadata at runtime:

```typescript
import { getContext } from '@microsoft/power-apps/app';

const ctx = await getContext();

// App context
const appId = ctx.app.appId;
const environmentId = ctx.app.environmentId;
const queryParams = ctx.app.queryParams;

// User context
const fullName = ctx.user.fullName;
const objectId = ctx.user.objectId;
const tenantId = ctx.user.tenantId;
const userPrincipalName = ctx.user.userPrincipalName;

// Host context
const sessionId = ctx.host.sessionId;
```

## Application Lifecycle Management (ALM)

### Deploying to a Solution

```powershell
# Push to preferred solution (default)
pac code push

# Push to a specific solution
pac code push --solutionName <solutionName>
```

### Adding to a Solution in Power Apps UI

1. Go to [Power Apps](https://make.powerapps.com/) > Solutions
2. Select your solution
3. Add existing > App > Code app > select your app

### Pipeline Deployment

Once in a solution, use **Power Platform Pipelines** to deploy across stages (Dev → Test → Prod).

## System Configuration

### Hosted App Code

When published, code is hosted on a publicly accessible endpoint. **Do NOT store sensitive data in the app code** — retrieve it from data sources after authentication.

### Hiding the Power Apps Header

Append `?hideNavBar=true` to the app URL:

```
https://apps.powerapps.com/play/e/{environmentId}/a/{appId}?hideNavBar=true
```

## Current Limitations

- No support for Storage SAS IP restrictions
- No Power Platform Git integration
- Not supported in Power Apps mobile or Power Apps for Windows
- No Power BI data integration (PowerBIIntegration function)
- No SharePoint forms integration
- No solution packager support
- Dataverse: no polymorphic lookups, actions/functions, FetchXML, or alternate keys (yet)

## Vite Template Notes

This template provides a minimal setup to get React working in Vite with HMR and ESLint rules. It is preconfigured with the `powerApps()` Vite plugin.

Two official React plugins are available:

- [@vitejs/plugin-react](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react) uses Babel (or oxc in rolldown-vite) for Fast Refresh
- [@vitejs/plugin-react-swc](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react-swc) uses SWC for Fast Refresh

The React Compiler is **not** enabled by default due to its impact on dev/build performance. See [React Compiler installation docs](https://react.dev/learn/react-compiler/installation) to add it.
